# Demo 导入指南

> 如果你拿到一个新下载的 BO3/BO5 整场比赛压缩包，不知道怎么把它变成研究工作台里能对比的数据，这篇指南会带你走完从下载到可用的全部步骤。

---

## 1. 我应该下载什么？

请下载**完整的 BO3（三局两胜）或 BO5（五局三胜）比赛包**，通常是 `.rar`、`.7z` 或 `.zip` 格式，里面包含一场比赛所有地图的 `.dem` 文件。

> ❗ 不要只下载单张地图的 Demo。单张地图无法在系统里构成"队伍 vs 队伍"的系列对比——需要一整场比赛的多张地图，才能正确建立两支队伍在该场比赛中的 team–map 记录。

---

## 2. 下载后放到哪里？

把下载好的压缩包（`.rar` / `.7z` / `.zip`）或裸 `.dem` 文件放进 `data/raw/` 下的一个子目录，建议按批次命名：

```
data/raw/
├── falcons-mirage/          ← 已有目录（勿动）
├── 2026-07-new-batch/       ← 你新建的目录
│   ├── iem-cologne-major-2026-g2-vs-spirit-bo3.rar
│   └── blast-bounty-2026-falcons-vs-nav1-bo3.zip
└── ...
```

不需要解压、改名或整理目录结构。系统可以直接从压缩包里读取文件列表。

---

## 3. 放好后做什么？——运行预检

运行预检脚本，它会扫描目录里的所有 `.dem`、`.zip`、`.rar` 和 `.7z` 文件，列出每张地图、检查是否有重复，然后输出一份 JSON 报告。

```powershell
python scripts/preflight_demo_archives.py data/raw/2026-07-new-batch --output reports/new-batch-preflight.json
```

### 预检会告诉你：

- **这个目录里有哪些地图？**（例如 `de_mirage`、`de_dust2`、`de_inferno`……）
- **有没有未知地图？** 文件名不包含可识别地图名称的会被标为 `unknown`
- **有没有重复？** 相同文件名和大小的 Demo 会被标为重复候选，方便你决定是否跳过
- **哪些压缩包需要 7-Zip？** `.rar` 和 `.7z` 文件的枚举需要 7-Zip 支持，系统不会因此崩溃，会在报告中明确指出

### 预检不会做：

- ❌ 不会解压任何文件
- ❌ 不会解析 Demo 内容
- ❌ 不会重命名或移动文件
- ❌ 不会判断队伍阵容是否正确
- ❌ 不会断言比赛是否已可用

> 预检只是"看一眼"文件名和归档目录结构，**不能证明队伍、阵容期或解析成功**。

---

## 4. 预检通过后——把报告交给 Codex

预检 JSON 报告就是你交给 Codex 的"导入清单"。Codex 会根据这份清单：

1. **导入解析**——解压并解析每张地图的 `.dem` 文件
2. **校验队伍和阵容**——确认解析结果与登记的比赛信息一致
3. **富化数据**——补充经济快照、装备事件、击杀链等衍生数据
4. **构建系列**——将同一场比赛的多张地图组织成 `team–map series`
5. **覆盖审计**——检查每支队伍在每个地图上是否达到最低样本量

你只需要说"请处理这份预检报告"，然后把 JSON 文件内容提供给它即可。

---

## 5. 一场 BO3/BO5 如何贡献 team–map 记录？

一场 BO3 或 BO5 中，两支队伍会在多张地图上各打半场（T/CT）。每张地图的 Demo 解析后构成一条 team–map 记录。举个例子：

```text
BO3: Falcons vs Spirit
├── Map 1: de_mirage  → Team Falcons 的 mirage 记录 + Team Spirit 的 mirage 记录
├── Map 2: de_dust2   → Team Falcons 的 dust2 记录 + Team Spirit 的 dust2 记录
└── Map 3: de_inferno → Team Falcons 的 inferno 记录 + Team Spirit 的 inferno 记录
```

所以一场 BO3 可以同时为**两支队伍**、**三张地图**各贡献一条记录，共 **6 条 team–map 记录**。

> ⚠️ 但这不代表任何队伍在任何地图上的样本已经达到最低门槛（目前每队每图至少 5 场、30 个有效样本）。预检本身不判断样本量——那是导入解析后的覆盖审计要做的事情。

---

## 6. 完整流程（一图流）

```
下载 BO3/BO5 .rar/.zip
         │
         ▼
放入 data/raw/<批次目录>/
         │
         ▼
运行 preflight_demo_archives.py
         │
         ▼
得到预检 JSON 报告
         │
         ▼
将报告交给 Codex
         │
         ▼
Codex 执行：
  ├─ 导入解析（import_match_archives）
  ├─ 富化（经济快照、装备事件……）
  ├─ series 构建（build_team_map_series）
  └─ 覆盖审计（audit_research_coverage）
         │
         ▼
数据显示在研究工作台
```

## 常见问题

**Q: 我只有一张地图的 .dem，能导入吗？**
可以，但只有一场比赛的一张地图无法构成系列对比，也不会进入跨战队比较的样本集。建议尽量下载完整的 BO3/BO5。

**Q: 报告显示某个 .rar 需要 7-Zip，但我没有安装？**
预检不会崩溃，其他 `.zip` 和 `.dem` 文件仍会正常处理。未枚举的 `.rar`/`.7z` 在报告中会明确标注。安装 [7-Zip](https://www.7-zip.org/) 后重新运行即可。

**Q: 报告里出现了 `unknown` 地图，怎么办？**
如果文件名确实不包含常见地图名称（如 `de_mirage`、`de_dust2` 等），可能是 Demo 命名不规范。你可以手动记录下来，导入时 Codex 会在解析后校验实际地图名。

**Q: 报告显示有重复候选项，该怎么办？**
预检只是提醒你同一个文件出现了多次（例如既在压缩包里又作为裸 .dem 存在）。这通常不会造成问题，导入解析时会自动去重，优先使用压缩包内的成员而不是裸 .dem。

**Q: 预检通过了是不是就可以直接看数据了？**
**不是。** 预检只是目录层面的文件名检查。数据要经过"导入 → 富化 → series 构建 → 覆盖审计"四个步骤后，才会出现在研究工作台中。预检通过只代表"可以进入导入流程"。
