一、路线矩阵（逐回合路线矩阵）
─────────────────────────────────

1.1 矩阵尺寸

  ┌──────────────┬──────┬──────┬──────────┐
  │ 队伍·阵营    │ 行数  │ 列数  │ 完整路线  │
  ├──────────────┼──────┼──────┼──────────┤
  │ Falcons T    │  9   │  4   │ 6 条     │
  │ Falcons CT   │ 12   │  4   │ 8 条     │
  │ FURIA T      │ 12   │  4   │ 7 条     │
  │ FURIA CT     │  9   │  4   │ 7 条     │
  └──────────────┴──────┴──────┴──────────┘

  每行 4 个单元格（20s、40s、60s、结果），单字符文本。

1.2 拥挤度

  ✅ 1440×900：无拥挤风险。12×4 = 48 格在 960px+ 内容宽度下
     每格约 80px × 36px，单字符（A/B/中/散/后/—/胜/负）无溢出。

  ✅ 1024×768：仍可接受。内容宽度约 710px，每格约 59px × 36px，
     单字符绰绰有余。hover tooltip 的较长中文文本不会截断。

1.3 颜色可辨识度

  单元格颜色方案：

  ┌─────────┬──────────┬────────────────────────────────────┐
  │ 标签     │ 颜色      │ 视觉评价                           │
  ├─────────┼──────────┼────────────────────────────────────┤
  │ A 区     │ #9a4d39  │ 红褐色，与 LOSS 暗红接近，易混淆    │
  │ B 区     │ #27725e  │ 绿色，与 WIN 深绿接近，易混淆        │
  │ 中路     │ #465f9d  │ 蓝色，唯一冷色，辨识度最高            │
  │ 分散站位  │ #626978  │ 灰蓝，中性，没问题                   │
  │ 后场     │ #363d48  │ 深灰，与背景接近，可辨识但有难度      │
  │ 回合已结束│ #171e28  │ 接近背景色，强调"不活跃"状态，合理   │
  │ 胜       │ #246747  │ 深绿，与 B 区的绿色接近              │
  │ 负       │ #783844  │ 暗红，与 A 区的红褐色接近            │
  └─────────┴──────────┴────────────────────────────────────┘

  ⚠ 发现：A ↔ 负、B ↔ 胜 的色相重叠。当用户快速扫视矩阵时，
  可能把 A 区路线误读为输掉的回合，把 B 区路线误读为赢下的
  回合。建议在 A/B 单元格内保留字母标签「A」「B」已缓解此问题
  （当前实现已经做到了，单元格内有单字符文本）。

  结论：功能区分的首要锚点是单元格内的文字标签，颜色为辅，
  当前方案在可接受范围内。


二、开局阵型对比（0:20 开局阵型对比）
─────────────────────────────────────────

2.1 阵型标签长度

  Falcons T:  "A1·B0·中3·后1"     ≈  11 字符宽（含中文）
  Falcons CT: "A2·B0·中2·后1"     ≈  11 字符
  FURIA T:    "A2·B0·中2·后1"     ≈  11 字符
  FURIA CT:   "A2·B2·中1·后0"     ≈  11 字符

2.2 拥挤度

  ✅ 1440×900：两列布局，每列约 450px，11 字符居中显示无压力。

  ⚠ 1024×768：两列布局每列约 310px。标签本身无溢出风险，
  但卡片内包含三段文字（标题 + 摘要 + 证据回合），整体垂直
  高度约 120px，两列卡片并排时仍可完整显示。

  阵型标签中混合了拉丁字母（A/B）、中文（中/后）和间隔号（·）。
  如果浏览器默认字体不支持中·西混排，可能出现 A 和 1 对齐抖动。
  当前 CSS 已声明 PingFang SC / Microsoft YaHei 字体栈，问题不大。


三、三阶段站位时间线
───────────────────────

3.1 布局

  3 列，每列一个小地图（position_snapshot_map），height=330px。

3.2 拥挤度

  ⚠ 1440×900：每列约 330px 宽，小地图上显示的标签格式为
  「A 区 33%」或「中路 25%」等。由于 font-size 为 11px，
  标签不会溢出，但可能相互重叠（当多个区域聚集在同一位置时）。
  position_snapshot_map 使用 median 坐标聚合，中心发散绘制，
  重叠概率依数据分布而定。

  ⚠ 1024×768：每列约 230px；小地图从 330px 缩小到约 230px
  宽(同比例缩放到约 230px 高)。显示内容同步等比缩小，
  文字字号保持 11px 可能相对变大。但地图可读性下降，
  建议对 1024 以下屏幕考虑 2 列或 1 列。

3.3 文字截断

  caption 较长（例如 "没有仍在进行且可定位的有效回合。" 或
  "N 个有效回合中，M 个以XXX为多人重心"），在 230px 宽的
  列中可能换行。Streamlit caption 默认不截断，会多行显示，
  视觉上可接受但会增加列高，引起列间错位。


四、重复执行组
─────────────────

4.1 展示内容

  每个重复路线显示为一张 tactical-finding 卡片 + 最多 6 个
  「回看 Rxx」按钮（并排）。

4.2 拥挤度

  ✅ 1440×900：卡片宽度约 450px，按钮 6 个并排无拥挤。

  ⚠ 1024×768：卡片宽度约 700px（全宽布局），按钮 6 个并排
  时每个按钮约 110px，可接受。但如果单路线有超过 6 个证据
  回合，按钮会换行到第二行。

  当前 `min(6, len(evidence_rounds))` 限制最多 6 个按钮。


五、页面长度
─────────────

5.1 内容清单（从上到下）

  ┌──────────────────────────────────────┬──────────┐
  │ 区块                                │ 估计高度  │
  ├──────────────────────────────────────┼──────────┤
  │ 控制栏（队伍/阵营/热区时间滑块）     │  ~80px   │
  │ 小地图 + 首杀转化 + 热区表格         │ ~750px   │
  │ caption × 3                         │ ~100px   │
  │ 开局阵型对比卡片 × 2                 │ ~200px   │
  │ caption                             │  ~30px   │
  │ 三阶段站位时间线（3 小地图）          │ ~400px   │
  │ caption × 3                         │  ~90px   │
  │ 逐回合路线矩阵                       │ ~500px   │
  │ caption                             │  ~40px   │
  │ 回看控制（下拉框 + 按钮 + 说明）      │  ~60px   │
  │ 重复执行组卡片 × 1-3 + 按钮          │ ~250px   │
  │ caption / info                       │  ~50px   │
  ├──────────────────────────────────────┼──────────┤
  │ 合计                                │~2550px   │
  └──────────────────────────────────────┴──────────┘

  1440×900 视口：内容高度约 2550px，视口 900px，需滚动约 3 屏。

  1024×768 视口：内容高度约 2800px（换行增加高度），需滚动约 4 屏。

  结论：页面长度属于合理范围。每个区块相对独立，用户通过滚动
  自然浏览不同分析维度。不建议将多区块折叠或分页——这违背了
  "一览"复盘页面的设计目标。

  切换时矩阵行数在 9-12 之间变化，矩阵容器高度自动适应。
  无固定高度容器导致的内容溢出风险。

  Falcons T 和 FURIA CT 没有重复路线，切换时「重复执行组」
  区块显示 info 提示文字。视觉上从「有内容」切换到「无内容」
  时高度跳跃约 200px，行为正常。


七、总结与建议
───────────────

7.1 必要改动（已满足）

  - [x] 路线矩阵单字符标签无拥挤
  - [x] 中文文本无额外空格或对齐问题
  - [x] 颜色虽有色相重叠，但有文字标签兜底

7.2 建议优化（低优先，Codex 后续可处理）

  1. 三阶段时间线在 1024px 以下改为 2 列 + 1 列叠放
  2. 路线矩阵 A 和 LOSS 的颜色差异加大（A→#b25740，LOSS→#6a2530）
  3. 路线矩阵 B 和 WIN 的颜色差异加大（B→#1f8a6f，WIN→#1f5d3a）
  4. 阵型卡片内的「回看 Rxx」按钮在 4+ 个时改为 2 行排列
  5. caption 文字统一增加 word-break: break-word 防止长 URL 溢出
